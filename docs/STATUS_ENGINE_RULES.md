# Status Engine Rules

## Scope

Milestone 2 computes business state from immutable inputs. It performs no SQLite queries, filesystem access, Jellyfin scanning, AniList requests, Discord delivery, scheduling, or GUI work. The same input values always return the same decision.

AniList status, tracker workflow, server presence, episode coverage, and review status are separate values. A releasing title may therefore be `ON_SERVER` with AniList status `RELEASING`, or `CURRENTLY_AIRING` with server presence `PARTIAL` and a nonblocking review note.

## Workflow Decision Table

Rules are evaluated from top to bottom. Active valid manual overrides are applied explicitly and reported in the decision.

| Archived | Blocking review | Server presence | Kind / release evidence | AniList status | Workflow |
|---|---|---|---|---|---|
| Yes | Any | Any | Any | Any | `ARCHIVED` |
| No | Yes | Any | Any | Any | `NEEDS_REVIEW` |
| No | No | `COMPLETE` | Any | Any | `ON_SERVER` |
| No | No | Not complete | Movie, digital confirmed | Any | `MOVIE_DIGITALLY_AVAILABLE` |
| No | No | Not complete | Movie, theatrical only | Any | `MOVIE_THEATRICAL_ONLY` |
| No | No | Not complete | Any | `NOT_YET_RELEASED` | `UPCOMING` |
| No | No | Not complete | Any | `RELEASING` or `HIATUS` | `CURRENTLY_AIRING` |
| No | No | Not complete | Any | `FINISHED` | `FINISHED_READY_TO_ADD` |
| No | No | Not complete | Any | Unknown/cancelled/inconsistent | `UPCOMING` plus warning |

An active force-workflow or force-presence override changes the result after ordinary computation. The result includes `override_changed_outcome`, applied override IDs, and a structured reason. Provider and scanner evidence are not overwritten. An archive override wins unless a newer active restore override exists.

## Server Presence And Coverage

| Evidence | Presence | Review |
|---|---|---|
| No confirmed mapping | `NOT_FOUND` | None |
| Confirmed path missing | `PATH_MISSING` | `MISSING_CONFIRMED_PATH` generated by review rules |
| Confirmed mapping, no reliable inventory | `UNKNOWN_COVERAGE` | None unless another conflict exists |
| Releasing, no currently aired episode present | `NOT_FOUND` | None |
| Releasing, some aired episodes present | `PARTIAL` | None |
| Releasing, every aired episode present | `COMPLETE` | None |
| Releasing, aired count unknown | `UNKNOWN_COVERAGE` | None |
| Finished, no expected episode present | `NOT_FOUND` | None |
| Finished, some expected episodes present | `PARTIAL` | None |
| Finished, every expected episode present | `COMPLETE` | None |
| Finished, expected total unknown | `UNKNOWN_COVERAGE` | None |
| Confirmed movie item/file present | `COMPLETE` | None |
| No confirmed movie item | `NOT_FOUND` | None |
| OVA/ONA/special target unresolved | `UNKNOWN_COVERAGE` when mapped, otherwise `NOT_FOUND` | `SPECIAL_MAPPING_REQUIRED` |

Coverage stores expected total, aired count, present numbers, missing aired numbers, missing expected numbers, duplicates, unknown-numbered files, special numbers, source, calculation time, confidence, and warnings. Future unaired episodes do not reduce current aired coverage. Extra and duplicate episodes are preserved as warnings; they do not make otherwise complete required coverage incomplete.

## Review Rules

Blocking review cases are generated for equally strong candidates, conflicting active targets or season scopes, missing confirmed paths, provider identity conflicts, movie-to-TV mappings without manual approval, unresolved OVA/ONA/special targets, and preserved legacy orphans.

No review is generated for no match, an empty candidate list, a new upcoming title, normal absence from the server, or temporary server/AniList availability. Operational errors belong to a later service layer. A review case carries an explicit blocking flag, allowing review metadata to coexist with an ordinary workflow where appropriate.

## Mapping And Rejection Rules

- One AniList entry can target one folder, a numbered season, a movie, or an explicitly approved set of multiple targets.
- Multiple AniList IDs may share one Jellyfin item with distinct season scopes.
- Season 1 does not satisfy Season 2; scope is explicit and is never inferred only from year or relation chronology.
- OVAs and specials can map to Season 00, a regular season, Movies, or a separate series. Season 00 is not forced.
- Active and superseded mappings coexist so history is retained.
- Rejections can target an exact path, stable item, generated candidate, or all automatic matching. Exact-path rejection does not reject other candidates. Expiration is supported.

## Examples

| Example | Provider / evidence | Result |
|---|---|---|
| Airing complete so far | Releasing; 4 aired; episodes 1-4 present | Presence `COMPLETE`; workflow `ON_SERVER`; provider remains `RELEASING` |
| Airing partial | Releasing; 5 aired; episodes 1-3 present | Presence `PARTIAL`; workflow `CURRENTLY_AIRING`; missing 4-5 in reasons |
| Finished complete | Finished; 12 expected; episodes 1-12 present | Presence `COMPLETE`; workflow `ON_SERVER` |
| Finished partial | Finished; 12 expected; episodes 1-10 present | Presence `PARTIAL`; workflow `FINISHED_READY_TO_ADD` |
| Upcoming | Not yet released; no mapping | Presence `NOT_FOUND`; workflow `UPCOMING`; no review |
| Theatrical movie | Finished movie; theatrical release only | `MOVIE_THEATRICAL_ONLY` |
| Digital movie | Finished movie; digital/Blu-ray confirmed | `MOVIE_DIGITALLY_AVAILABLE` |
| No server match | Finished title; empty candidate list | `FINISHED_READY_TO_ADD`; review `NONE` |
| Confirmed path missing | Prior confirmed mapping; path absent | Presence `PATH_MISSING`; blocking `MISSING_CONFIRMED_PATH`; workflow `NEEDS_REVIEW` |
| OVA unresolved | OVA has no confirmed parent/server scope | `SPECIAL_MAPPING_REQUIRED`; no automatic Season 00 assignment |
| Shared show folder | Season 1 targets Season 01 and sequel targets Season 02 in one item | Two valid mappings; neither season satisfies the other |

## Transition Events

Comparison produces typed data only: `TRACKING_STARTED`, `MOVED_TO_UPCOMING`, `STARTED_AIRING`, `NEW_EPISODE_AIRED`, `COVERAGE_BECAME_PARTIAL`, `COVERAGE_BECAME_COMPLETE`, `COVERAGE_LOST`, `SERIES_FINISHED`, `MOVIE_BECAME_THEATRICAL`, `MOVIE_BECAME_DIGITAL`, `FOUND_ON_SERVER`, `NO_LONGER_FOUND_ON_SERVER`, `MAPPING_CHANGED`, `REVIEW_REQUIRED`, `REVIEW_RESOLVED`, `ARCHIVED`, and `RESTORED`. Equal previous/current snapshots produce no event.
